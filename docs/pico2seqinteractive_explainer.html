01 · The Encoder

TMAG5273A magnetic rotary sensor · “Velocity Encoder”

There is no mechanical encoder in this instrument. The knob is a magnet on a spindle in front of a TI TMAG5273A 3D Hall-effect sensor (I²C address 0x35, on the main Wire bus GP4/GP5 at 400 kHz). The sensor reports the magnet’s absolute angle — 5,760 counts per revolution (1/16° resolution, CORDIC-computed) — and the firmware turns consecutive readings into relative motion with velocity-sensitive acceleration: turn slowly and you get surgical 0.008× steps; flick it and a single gesture sweeps up to 3.2× — a 400× dynamic range. No detents, no end stops, endless rotation.

The two jobs of the knob: with no step under edit it nudges a per-voice bipolar base offset (±0.75) for the selected parameter, reshaping the whole sequence; once a step is long-pressed for editing, it writes that step’s value directly.
WAY 1

Feel the Physics — velocity curve lab

Drag the knob (or scroll on it). The firmware measures your angular speed and multiplies every step by it.

Each 5 ms the driver reads the angle, computes the delta since last read (unwrapped across the ±half-rev boundary), and estimates angular speed over ≥8 ms windows with an adaptive EMA (α = 0.3 below 90°/s, 0.4 below 120°/s, 0.6 above; an 8°/s noise gate halves the estimate when you stop). Speed runs through the piecewise velocity curve below, is smoothed again (α = 0.08), and the result scales the increment: Δ = ticks × range/(5760 × 3) × velocityScale. Increments under 0.0005 are dropped as noise, and the target clamps at ±0.75.

Follow the Signal — magnet to music, one stage at a time

Nothing about the encoder is read “live” — it’s a sampled system. Core 0 polls every millisecond, but the sensor is throttled to one I²C read per 5 ms. Rotation becomes ticks (1/16° each), ticks become speed, speed becomes a multiplier, and only then does anything musical happen. WAY 3

Two Modes & the Shift-and-Scale Map

What the knob writes depends on context — and the base offset doesn’t add, it reshapes.

The knob’s ENC button (utility-tile bit 5) picks the target: a short press (<400 ms) cycles Velocity → Filter → Attack → Decay → Note → Octave → SlideTime; pressing any parameter button auto-selects that parameter and clears stale ticks. A long press (≥400 ms) enters Gate Length mode where the step pads set the Gate track’s length (2–16). The base offset is applied at every sequencer step, to all four voices, with Shift-and-Scale: positive offset out = base + seq×(1−base) (raises the floor), negative out = seq×(1+base) (lowers the ceiling) — the sequence keeps spanning its whole remaining range instead of slamming into a wall. Octave is special: the offset becomes round(base × 12) semitones, combined with the step’s own ±12, clamped to ±24.

02 · The Sliders

4-fader Alchemy tile · VL53L1X “air slider”

“Sliders” on Pico2Seq are two different instruments. The SliderModule tile is a custom I²C peripheral (a PY32F030 slave at address 0x08–0x0A on Wire1, GP14/GP15) with four 12-bit faders (0–4095) plus four buttons, polled round-robin every 4 ms. The air slider is a VL53L1X time-of-flight laser rangefinder (address 0x29) that measures your hand’s height above it — anything from 55 mm to 700 mm — and turns distance into a parameter value. There is no calibration step anywhere: fixed constants and a small deadband do all the work.

What each fader controls depends on a physical mode strap (GP7): low = Param mode (faders = Filter / Attack / Decay / Velocity), high = Utility mode (faders = Tempo 45–200 BPM / Swing / — / Gate Length). And a fader only records while its matching parameter button is held or Shift-latched.
WAY 1

Every fader shows its full journey: raw counts (0–4095), the 8-count deadband (below it, nothing is sent), the normalized 0–1 value, and the mapped musical unit. The air slider has a sharper rule: leave the 55–700 mm window and the value snaps to zero — it doesn’t hold the last distance.

WAY 2

Mapping Curves — from 0..1 to real units

The same normalized slider value becomes very different things depending on the parameter.

A slider value is always stored as a plain 0–1 float — the musical meaning is applied at the destination. Filter cutoff uses an “EXP” curve that is actually a square law — f = 120 + x²×4880 Hz (120–5000 Hz; Hypersaw/NoiseStorm engines use 150–8000). Attack is linear (0.002–0.75 s), decay is logarithmic (0.01–0.5 s), octave is a two-threshold step function (below 0.15 → −12 st, above 0.4 → +12 st), and Note indexes the scale table — 0–36 scale degrees spanning three octaves, quantized to whichever of the 13 scales is active. Drag the cursor to compare shapes.

WAY 3

Write-Path Theater — the audition a slider value survives

Five gates stand between a fader and a step. Watch values get through — or get rejected.

A slider movement is only recorded if it passes every check: the deadband (≥8 counts of change), the parameter arming (its button held/latched), the gate rule (Note writes are silently blocked on steps whose Gate is off), then it is clamped and quantized into the track (binary tracks threshold at 0.5, Note rounds to integers). Finally the preview: you only hear the change immediately if the step you’re editing is the step currently playing — otherwise it waits silently for its turn. During live playback the lidar records into whichever step is currently sounding, for the selected voice only.

03 · Parameter Sequencing

9 tracks × 4 voices · one shared counter · polymetric

Every voice owns nine tracks — Gate, Note, Velocity, Filter, Attack, Decay, Octave, GateLength, Slide — each just a ParameterTrack<float, 64>: an array of up to 64 plain float steps with its own length. There is no separate “gate track class”; Gate is simply the binary track whose length has a superpower: the Gate track’s length defines the whole pattern’s length. Every track is read at globalStep % ownLength from one shared, ever-increasing uClock step counter (a 16th note = 120 ticks at 480 PPQN) — so tracks of different lengths wrap independently and never drift out of phase. The combined pattern repeats every LCM of the lengths: that’s the polymetric engine.

The one fact that surprises everyone: shorten the Gate track to 8 and the pattern is 8 steps long — but the Note track (length 3, say) keeps cycling 0→1→2 against the global counter, so each of the 8 gate hits meets a different note. Full realignment takes LCM(8,3) = 24 steps. Tracks advance even on silent steps; Gate-off steps still update Filter/Attack/Decay — only Note and Octave are held while the gate is low.

WAY 2

Concentric Rings — see the modulo turn

The same nine tracks as rings around one counter. Different circumferences, one heartbeat.

Each ring is a track; its dots are its steps; the glowing dot is globalStep % length walking clockwise. Because all rings are driven by the same counter (not each other), a 3-step ring and an 8-step ring pass the top mark together only every 24 steps — that’s the realignment flash at the center. Shorten a ring and the pattern tightens; nothing ever needs re-syncing. This is why the firmware can resize any track mid-play.

WAY 3

Step → Sound — crossing the core boundary

Follow one step’s values into a VoiceState, through the lock-free queue, into the DSP.

Each step, Sequencer::processStep() reads all nine tracks into one VoiceState (note index, velocity, filter, attack, decay, octave, gate length, gate/slide flags). The encoder’s base offsets fold in here (Shift-and-Scale again). Core 0 then stages a ControlUpdate and pushes it into that voice’s SpscQueue<ControlUpdate, 8> — Core 1 pops at most one update per audio sample at the top of Voice::process(), so the audio thread never waits. If the queue is full the update coalesces in the staging struct and is retried every control loop — a final gate-off can never be lost. Try the burst button to see it.
