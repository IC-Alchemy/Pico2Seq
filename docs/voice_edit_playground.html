Pico2Seq — Voice Edit mode

An interactive user manual for the per-voice parameter editor added in PR #23 (plan-voice-editing-mode, merged 2026-09-11). The hardware below is simulated: click the buttons, turn the encoder, and the OLED behaves like the instrument. Everything on this page mirrors docs/voice-edit.md and the firmware source.

Cheat sheet

  • Enter Shift+Slider4 — all sequencers stop, audio mutes
  • 1 / 2 — previous / next parameter group
  • 3 / 4 — previous / next parameter in group
  • Slider 1–4 — choose voice V1–V4
  • Encoder — edit the shown base
  • 5 hold — fine adjust (×0.1)
  • 6 hold 0.7 s — reset base to preset
  • 7 — help overlay on/off
  • 8 — exit (edits kept, still stopped)
  • Play — hear the edited patch

Try this

  1. Press 8+Slider 4 together to enter. Release everything.
  2. Tap 2 a few times — groups; 4 — parameters inside one.
  3. Scroll the encoder. The modified star * appears.
  4. Tap 7 — the on-device help overlay.
  5. Hold 6 ~1 s to reset this base to the preset.
  6. Tap 8 to exit, then Play.

Getting in and out

Enter

  • Hold Shift (button-tile button 8) and press slider button 4.
  • All four sequencers stop and audio is muted; the OLED switches to EDIT V1…V4.
  • Release the entry buttons before editing — the editor waits for all buttons to be up first.
  • Slider buttons 1–4 then select the voice being edited. Each voice remembers its own parameter cursor.

Exit

  • Press button 8. Edits are kept and transport stays stopped.
  • Button releases from the editor are consumed first, so nothing “falls through” to normal controls; the GP7 Param/Utility switch is re-sampled after exit.
  • Press normal Play to hear the edited patch in its sequence.

What is frozen while editing

  • Faders, the lidar, touch pads, transport chords and the GP7 Param/Utility switch do not change the patch or sequence during Voice Edit.
  • Step recording is suspended too — the lidar would otherwise write modifiers while you tweak bases.
  • Audio keeps running internally (envelopes release, edits are queued to Core 1), so scalar edits avoid oscillator rebuilds; structural changes wait for gate-low.
  • Button 7 is Help in these stages; step audition is not implemented yet.

Changes are RAM-only (for now)

  • Edits last until a preset is loaded or power is lost. Auditioning and saving patches across power cycles are later stages.
  • Loading a preset replaces the bases without reseeding the modifier lanes.

Base + modifier — how the lidar reshapes a patch

Every numeric sound setting now has a per-voice base (what the encoder edits). The lidar no longer stores absolute values: it records only a signed modifier — its calibrated 55–1200 mm range is normalized to 0–1 and the midpoint is neutral. At playback the two combine in the normalized parameter domain:

modifier = lidarNormalized − 0.5   ·   effective = clamp(base + modifier, 0 … 1)

The documented example: a 70 % velocity base with recorded lidar readings of 25 %, 50 % and 75 % plays at 45 %, 70 %, 95 %. Moving the base later transposes all three recordings — they are never rewritten. Limits clamp.

An 8-step Velocity lane. Record writes the current lidar modifier into every step (as live recording does), Randomize randomizes modifiers (as the randomize button does), Neutral is what new/reset steps get. Then drag the Base slider — the bars follow the base, the stored modifiers don’t change.

Storage stays in the sequencer’s own units (Note 0–36, Gate length 0.001–1, other lanes 0–1); the step OLED shows the stored modifier as +x.x% mod. New and reset steps — including hidden note values of silent steps — start neutral. There is no separate depth control in this stage.

Special lanes

  • Gate stays a trigger pattern: the base enables/disables the whole pattern (base AND step).
  • Slide: base on = slide everywhere; base off = the recorded per-step Slide bits decide (base OR step).
  • Note bases are scale steps; Octave bases are quantized semitones from −24 to +24.
  • Attack/Decay use a logarithmic 1 ms–10 s domain; their lanes never touch sustain or release.
  • Engine-specific lanes keep their own curves and units — Hard-sync’s Slave tuning, string T60, FM ratio, recipe macros.

Parameter catalogue

The editor only offers what the current engine and enabled processors use — everything else is hidden, and group navigation skips empty groups. Configure a voice below to see exactly which parameters its editor exposes. In the last column, BASE + STEP MOD means a sequencer lane also modifies this base; PATCH BASE means the encoder value is the whole story.

Not editable (engine implementation state, not patch values): oscillator phases, random seeds, buffer sizes, DSP callback pointers, numerical stability constants. When the engine or recipe changes, resetting a parameter uses the loaded preset’s value adapted to the new engine’s valid ranges.

Outside the editor: what changed in normal play

  • The encoder now edits the base of whichever sequenced parameter it targets — it no longer overwrites the selected step’s stored value. The OLED shows B:<name> <value> for that base.
  • When a step is selected, its OLED line shows the stored signed modifier, e.g. +23.4% mod, instead of an absolute value.
  • Lidar recording during playback writes modifiers (midpoint = neutral) into the selected voice’s lanes — normalized 55–1200 mm exactly as in the lab above.
  • Randomize randomizes modifiers; new/reset steps are neutral.
  • The editor’s Engine and Recipe selections re-point the voice’s parameter layout, so lane meanings change together: picking a hard-sync waveform turns the Velocity lane into Slave tuning; ordinary waveforms restore Velocity. SVF offers LP/BP/HP; ladder filters offer the six native responses (LP24, LP12, BP24, BP12, HP24, HP12).

Sequenced bases are engine-aware

The Sequenced bases group always exists, but each engine decides what its Filter / Attack / Decay lanes mean — the editor renames them so the OLED never lies. Examples (see the catalogue’s engine selector):

  • Oscillators: Cutoff / Attack / Decay mean themselves.
  • Hard sync: Note → Master, Velocity → Slave (±24 semitones of slave tuning).
  • Waveguide: Cutoff → Bright, Attack → Pick, Decay → T60.
  • Hypersaw: Attack → Detune, Decay → Mix.
  • Noise FX: Cutoff → Color, Attack → Regen, Decay → Chaos.
  • Recipes: the three timbre lanes become the recipe’s macros — e.g. FM: Cutoff → Index, Attack → Ratio, Decay → Feedback.

Good to know

  • Independent voices. All four voices keep separate bases, cursors and modified markers; editing one never touches the others. Voices 1–2 keep software gates; 3–4 are audio-only.
  • Reset is per-parameter. Holding button 6 resets only the selected base, and to the loaded preset’s value — not a factory default. If you switched engine since loading, the preset value is adapted to the new engine’s ranges.
  • Navigation is filtered. Unavailable parameters are skipped in both directions and empty groups are skipped when changing groups; the cursor never lands on a dead entry.
  • Discrete vs continuous. Toggles, choices, Note and Octave step in whole increments (Octave in octaves); continuous parameters sweep their domain, with logarithmic domains for all time parameters and the high-pass cutoff, and curve-mapped domains for lane-bound values.
  • Firmware compilation and upload don’t verify physical controls or listening — check those on the instrument after flashing.
